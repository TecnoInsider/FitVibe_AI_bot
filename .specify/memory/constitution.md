# FitVibe Constitution

## Core Principles

### 1) Пользовательский путь прежде всего
Любые изменения должны сохранять основной путь Telegram WebApp: быстрое открытие, понятные шаги, минимум блокировок. Онбординг показывается только новым пользователям.

### 2) Совместимость с Telegram и browser‑debug
Код должен корректно работать в Telegram WebApp и в debug‑режиме браузера. Debug‑режим включается только явным параметром и не влияет на продакшен‑поведение.

### 3) Минимум зависимостей, максимум явности
Добавлять библиотеки только при необходимости. Любые новые зависимости должны быть обоснованы. Ошибки — логируются явно, пользователь получает понятное сообщение.

### 4) API‑контракты стабильны
Любые изменения, влияющие на n8n/webhook payload, фиксируются в документации и проверяются с бэкендом. Переиспользовать существующие вебхуки, если не оговорено иначе.

### 5) UI‑консистентность
Онбординг должен визуально соответствовать текущему дизайну FitVibe (цвета, типографика, тональность). Встраиваемая форма не ломает основной UI.

## Технические ограничения

- Стек: Vite + React + TypeScript.
- Маршрутизация: react-router-dom (MemoryRouter).
- Источник данных профиля: n8n webhooks.

## Процесс разработки

- Сначала документируем изменения в Spec Kit (spec/plan/tasks).
- Затем вносим кодовые изменения с проверкой локального запуска.
- Любые dev‑заглушки должны быть ограничены debug‑режимом.

## Governance

- Конституция имеет приоритет над любыми локальными решениями.
- Любое отступление документируется в соответствующей спецификации.
