# Feature Specification: Onboarding + Debug Mode Integration

**Feature Branch**: `[001-onboarding-integration]`
**Created**: 2026-02-02
**Status**: Draft
**Input**: User description: "Встроить многошаговый онбординг, показывать только новым пользователям. Добавить debug‑режим для запуска в браузере с параметром telegram_id и диагностической панелью."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Новый пользователь проходит онбординг (Priority: P1)

Новый пользователь открывает Telegram WebApp, видит многошаговую форму, заполняет данные и получает доступ к профилю.

**Why this priority**: Это основной entry‑point для новых пользователей, без него приложение не выполняет ключевую функцию персонализации.

**Independent Test**: Открыть приложение с новым `telegram_id`, заполнить форму, убедиться, что профиль доступен и онбординг больше не показывается.

**Acceptance Scenarios**:

1. **Given** профиль отсутствует, **When** пользователь заполняет форму и отправляет, **Then** данные сохраняются и отображается профиль.
2. **Given** профиль отсутствует, **When** пользователь обновляет страницу, **Then** онбординг сохраняет введённые данные (через localStorage) до отправки.

---

### User Story 2 - Существующий пользователь видит профиль сразу (Priority: P1)

Пользователь, у которого уже есть профиль, не видит онбординг и сразу попадает на профиль.

**Why this priority**: Необходимо избежать повторного прохождения онбординга и обеспечить быстрый вход.

**Independent Test**: Подставить `telegram_id` существующего пользователя и убедиться, что отображается профиль без формы.

**Acceptance Scenarios**:

1. **Given** профиль существует, **When** пользователь открывает приложение, **Then** онбординг не показывается.

---

### User Story 3 - Debug‑режим в браузере (Priority: P2)

Разработчик открывает приложение в браузере с `?debug=1&telegram_id=...`, получает доступ к UI и видит диагностическую панель.

**Why this priority**: Ускоряет разработку и поддержку без Telegram клиента.

**Independent Test**: Открыть браузерную ссылку с параметрами и убедиться, что UI работает и отображается debug‑панель.

**Acceptance Scenarios**:

1. **Given** включён `debug=1`, **When** URL содержит `telegram_id`, **Then** app работает без Telegram SDK.
2. **Given** debug включён, **When** пользователь открывает страницу, **Then** отображается диагностическая панель.

---

### Edge Cases

- `getProfile` возвращает 500/ошибку — UI остаётся доступным, пользователь получает уведомление.
- Отсутствует `telegram_id` и нет Telegram SDK — показывается понятная ошибка.
- Некорректные значения в форме — валидация блокирует отправку.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST показывать онбординг только при отсутствии профиля.
- **FR-002**: Система MUST сохранять профиль через `user_profile_write`.
- **FR-003**: Система MUST редиректить на профиль после успешного сабмита.
- **FR-004**: Система MUST поддерживать debug‑режим с `?debug=1`.
- **FR-005**: В debug‑режиме система MUST принимать `telegram_id` из URL.

### Key Entities

- **UserProfile**: профиль пользователя (tg_id, name, age, height, weight, activity_level, goal).
- **OnboardingPayload**: payload для `user_profile_write` (данные формы + telegram_id).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Новый пользователь завершает онбординг < 2 минут.
- **SC-002**: Существующий пользователь видит профиль без формы за < 2 сек.
- **SC-003**: Debug‑режим работает в браузере с одним URL‑параметром.
